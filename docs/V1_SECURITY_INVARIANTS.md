# V1 Security Invariants Extracted for V2

This document records guarantees and failure lessons found in V1 source,
tests, installers, and systemd templates. V2 preserves the useful guarantees,
strengthens ambiguous ones, and explicitly records replacements.

## Preserved and strengthened

1. Firewall policy is default deny for input and forwarding. Strict VPN mode
   also defaults output to deny.
2. Every permitted Internet egress path is interface-pinned to WireGuard. A
   physical-uplink bootstrap exception is constrained by endpoint address,
   UDP port, and WireGuard mark.
3. Container traffic cannot use the physical uplink. VPN-only masquerading is
   enforced at both forwarding and NAT layers.
4. IPv6 cannot silently bypass an IPv4-only policy. Disabled mode drops IPv6
   at an early priority; native and VPN modes have equivalent explicit policy.
5. Conntrack state must not create a VPN-loss escape hatch. Output has no
   blanket established/related accept; container-to-physical forwarding is a
   hard drop before stateful rules.
6. Rules generated by the product are identifiable by owned table names and
   deterministic comments. Reconciliation may repair owned drift but leaves
   third-party tables alone.
7. Configuration, IP/CIDR, port, interface, endpoint, and runtime claims are
   validated before they reach nftables. `/0`, malformed values, ambiguous
   interfaces, and protected ranges are rejected.
8. Dynamic blocking is additive by provenance. Removing a threat-feed claim
   cannot remove a manual, GeoIP, or temporary claim for the same address.
9. Apply is checked before mutation and is atomic at the nft transaction
   boundary. The last-known-good generation is retained on failure.
10. Safe apply is durable: a pending generation and deadline survive CLI and
    daemon death. An independent systemd rollback path can restore the prior
    owned generation.
11. Endpoint DNS results are bounded, validated, cached atomically, audited,
    and represented as runtime sets. DNS failure retains only safe recent
    endpoints and never widens egress.
12. Privileged operations cross one narrow boundary. Unix peer credentials,
    strict request schemas, request-size limits, and argument arrays prevent
    claimed identities, shell interpolation, and arbitrary commands.
13. Sensitive files and sockets have explicit ownership and modes. Symlinked
    config/state paths, world-writable parents, and unsafe executable owners
    are rejected by `doctor`.
14. The dashboard is read-only and local by default. It has no control socket,
    Docker socket, secret display, or mutable HTTP endpoint.
15. Threat feeds and GeoIP are optional integrations. Timeouts, response-size
    limits, strict parsing, sanity thresholds, and stale-feed policy prevent a
    malformed external source from becoming allow-all.
16. Audit records cover policy loads, applies, commits, rollbacks, drift,
    endpoint changes, claims, rejected requests, and recovery without secrets.

## V1 hazards explicitly not repeated

- `flush ruleset` is not used during normal V2 operation.
- V2 does not trust free-form ChatOps commands or execute shell strings.
- V2 does not persist timed trust grants as permanent entries.
- V2 does not treat a marker comment alone as proof; observed JSON state and
  owned-object checks are required.
- V2 does not let configuration parsing or status collection mutate policy.
